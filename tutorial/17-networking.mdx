# Networking

## Fetching

`fetch` makes an HTTP GET request and returns a `Result[Response, str]`:

```mimic
module main

fn main() {
    let r = fetch("http://example.com/") else { return }
    print(r.status)
    print(get(r.headers, "content-type"))
    print(≢ r.body)
}
```

Several requests written one after another are **in flight at the same time**: each `let` starts its request, and the program waits only where a result is used ([chapter 10](10-parallel-by-default.mdx)):

```mimic
let news = fetch("http://news.example/")
let weather = fetch("http://weather.example/")
print(summary(news) + summary(weather))     // both were downloading at once
```

`request(method, url, headers, body)` sends any method, with headers and a body:

```mimic
request("POST", "http://api.example/notes", ["content-type": "text/plain"], "remember the milk")
```

`https://` addresses are not supported yet; they return an `Err` that says so.

## Serving

A server is a function from `Request` to `Response`. Routes are ordinary `match` patterns, and route captures are typed:

```mimic
fn handle(req: Request) -> Response {
    match (req.method, req.path) {
        ("GET", "/") => ok("hello"),
        ("GET", "/users/{id: i64}") => ok("user #{id}"),
        ("POST", "/notes") => respond(201, "saved: {req.body}"),
        _ => not_found(),
    }
}

fn main() {
    print(serve(8080, handle))               // runs until the program is stopped
}
```

If `handle` is pure, as here, every request is handled in parallel. If it prints or writes files, requests are handled one at a time, in order, so its effects never interleave. Either way you write the same code.

## A server and its client in one program

Because a server with a pure handler only has overlapping effects, starting it with `let` runs it in the background like any other implicit future:

```mimic run
module main

fn handle(req: Request) -> Response {
    match req.path {
        "/hello/{name}" => ok("hello, {name}!"),
        _ => not_found(),
    }
}

fn server(port: i64) -> Result[i64, str] { serve_requests(port, handle, 3) }

// wait until the server answers (it starts at the same moment we do)
fn when_up(url: str, tries: i64) -> Result[Response, str] {
    match fetch(url) {
        Ok(r) => Ok(r),
        Err(e) => if tries <= 1 { Err(e) } else { sleep(20ms); when_up(url, tries - 1) },
    }
}

fn main() {
    let port = 30000 + pid() % 20000
    let base = "http://127.0.0.1:{port}"
    let s = server(port)                         // starts serving in the background
    print(show(when_up(base + "/hello/ada", 100)))
    let a = fetch(base + "/hello/grace")         // these two overlap
    let b = fetch(base + "/missing")
    print(show(a))
    print(show(b))
    print(s)                                     // the server stops after 3 requests
}

fn show(r: Result[Response, str]) -> str {
    match r {
        Ok(resp) => "{resp.status}: {resp.body}",
        Err(e) => "failed: {e}",
    }
}
```

```output
200: hello, ada!
200: hello, grace!
404: not found
Ok(3)
```

## TCP

For other protocols, use TCP sockets directly:

```mimic
let sock = tcp_connect("example.com", 80) else { return }
print(send(sock, "GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n"))
let reply = receive(sock, 4096) else { return }
print(lines(reply)[0])                          // HTTP/1.1 200 OK
close(sock)
```

A server side uses `tcp_listen(port)` and `tcp_accept(listener)`. All TCP calls happen in program order.
